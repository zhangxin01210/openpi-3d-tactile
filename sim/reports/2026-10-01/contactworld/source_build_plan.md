## 估计

这是基于本机条件和依赖链的工程估计，不是已测得的编译时间或成功保证：顺利时约一个工作日完成最小环境；通常预留 **1–3 天**；出现旧代码/CUDA/扩展冲突时可能需要 **3–5 天或更久**。

| 阶段 | 预估耗时 | 验收点 |
| --- | --- | --- |
| 独立构建环境、源码和 cuDNN、必要补丁 | 1–3 小时 | Python 3.8 + CUDA 12.8；依赖和补丁记录可复现 |
| 构建单架构 Torch 2.4.1；首轮 CUDA 检查 | 2–8 小时 | arange、索引、矩阵乘法、卷积等在 sm120 上运行 |
| gymtorch 和实际需要的其他扩展 | 1–3 小时 | Gym 张量交换与 GPU 相机张量正常；torchvision 若确有依赖则重建 |
| ContactWorld USB/Peg 最小在线测试 | 2–6 小时 | reset/step、SDF/TacFF、RGB-D、状态与动作时序检查 |

阶段估计不包含多轮全量重编译、直连网络异常或上游原生闭源模块故障；训练、完整评测、新示范采集也不在其中。第一个值得停下汇报的节点是自编译 Torch 的 CUDA 运算与 gymtorch 通过，而不是仅 wheel 打包成功。

## 本机条件

- Ryzen 9 9950X，16 核 / 32 线程。
- 总内存约 249 GiB，核查时可用约 236 GiB。
- 所在分区剩余约 203 GiB；规划预留 50–100 GiB 的源码、构建中间产物和 wheel 空间，实际用量尚未测定。
- 已有 CUDA toolkit 12.8.93、GCC 11.5、CMake 3.28.3，省去了这部分安装。
- 当前 5090 的原生 Isaac Gym GPU PhysX 和现代 Torch CUDA 已分别通过，剩余难点集中在 Python 3.8 下的框架/扩展组合与完整 TacSL 链路。

## 构建范围与停止条件

[社区报告](https://github.com/escontra/gauss_gym/issues/13#issuecomment-4914476549)给出了 Python 3.8 + Torch 2.4.1 + CUDA 12.8 + sm120 的做法，涉及架构字符串解析、C++ 扩展支持列表和新版 cuDNN。它是第三方项目的经验，尚未在 ContactWorld 上复现。

采用独立构建环境并保存 wheel/补丁；保持现有 Isaac Sim 环境。只编译 sm120，先关闭非必要分布式与注意力优化，不照搬其可选的 FlashAttention 架构放宽补丁。优先通过最小算子与 Gym 张量探针，再决定剩余扩展。下载继续优先直连；之前对单个 269 MB 安装包的代理授权不扩展到新大文件。

若 Torch 已通过但 TacSL 的原生 SDF/GPU 张量仍被不可重编译的闭源组件阻塞，记录具体失败再总结，避免盲目反复重编译。若累计约两天仍未通过 Torch + gymtorch 第一关，也先汇报根因与剩余工作；这属于进度检查，并非再次把“需要自编译”本身作为淘汰理由。

Bench2Dex 可继续推进现成数据审查与训练/评估接口验证，参见[更新后的选型判断](../bench2dex/reconsideration.md)。
